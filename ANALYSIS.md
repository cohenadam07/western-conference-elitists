# WCE Pro analysis: savant_sql and savant_analyze

The Data Room (`savant_data`) pulls 500 rows a call, which is fine for one player or one team. A
whole-league question ("do teams shoot worse on the second night of a back-to-back, since 2010?") would
take thousands of calls. These two tools run the math on WCE's server instead. The AI sends one request,
the server reads only the rows it needs, and the answer comes back small, with sample sizes and how
confident to be. The brief is [research/analysis/BUILD.md](research/analysis/BUILD.md).

| tool | what it does |
|---|---|
| `savant_sql` | one read-only DuckDB `SELECT` over every Data Room table and season. 500 rows back, with the full count, rows scanned, each table's data-through date and the time. `dictionary: {sport, table}` answers what `savant_dictionary` answers |
| `savant_analyze` | a study over the full data: `compare`, `regress`, `stability`, `trend`, `distribution`. Gives intervals, cluster-robust errors, samples, warnings, a verdict, and what the study cannot account for |

Connector **3.8.0**. Founder tier only. **Nothing is charged:** there is no paywall, pricing or payment
code anywhere.

## Who sees the tools

- **Founder tier.** A `tier: "founder"` field on the key record in the Upstash keys hash, set only by
  `tools/keys/tier.mjs`. `checkKey` now returns it (`api/_keys.js`).
- **The open switch.** Set `PRO_ANALYSIS_OPEN=1` on Vercel and every valid key gets both tools. It is read
  per request and defaults to off.
- **The public address.** The public address, unknown and unchecked keys, and ordinary key holders list
  exactly what main lists, with main's up-front text. A test checks this against hashes of main's listing
  (`tools/analysis/public-main.json`, regenerated by `snapshot-main.mjs`).
- **When an unlisted address calls one anyway,** it gets a clear sentence back instead of "tool not found".
- **Where the tools are listed, `savant_sql` replaces `savant_data` and `savant_dictionary`.** It answers the
  same rows (any table, any season, filters, 500 rows) and the same dictionary. This is what keeps the
  founder listing under the cap: **89,698 characters** (cap 90,000). Without the fold it would be 95,924,
  because ordinary key holders are already at 91,365 on main (`savant_query`). The founder up-front text
  adds one sentence telling the AI to use `savant_sql` with `dictionary` wherever another tool says
  `savant_dictionary`.

## The engine

- **DuckDB 2.0** (`@duckdb/node-api` 2.0.0-r.1, pinned) runs inside `api/mcp.js` and is imported lazily, so
  a public call never loads it.
- **httpfs** is DuckDB's own signed build. It is installed once per copy into `/tmp`; nothing else can be
  installed or loaded.
- **Views.** There is one schema per sport and one view per table over all its seasons. The views read
  Parquet straight off the release with HTTP range requests, following GitHub's redirect to its file host.
- **The season trick.** Each season's URL carries `?p=/season=<s>/`. GitHub ignores it, and DuckDB reads it
  as a hive partition, so `WHERE season = '2024-25'` skips the other seasons' files without opening them.
- **Newest season first.** Each view lists the newest season first, because DuckDB takes a view's columns
  from the first file's footer. A question about the current season opens one file; any other season opens
  two footers at most (tested).
- **One query at a time per copy.** The function has one CPU, and the profiler writes one file.
- **A fresh engine every 10 minutes,** so a replaced file or a new season is picked up.
- **Statistics** live in `api/_stats.js` and `api/_analyze.js`. Regressions are computed in SQL from
  sufficient statistics and cluster score sums, so millions of rows never have to cross into JavaScript.

## Hosting: free, as decided

- **Parquet copies** of all 25 Data Room tables are release assets on the existing `dataroom` tag, beside
  the JSON: **511 files, 297 MB**, nothing in git. That is one file per sport, table and season, sorted by
  date, then team, then player; ~64k-row groups, zstd, statistics on.
  - Small tables went to the release too, so there is one host and one allowlist. `public/` grows only by
    the manifest (`public/dataroom/parquet.json.gz`, 127 KB).
  - The release now holds 642 assets; GitHub's limit is 1,000 per release.
- **One analysis-only table:** `nba.player_seasons`. These are Basketball Savant's own player-seasons:
  position group, the page's qualified flag, and the per-game line. It is not in the Data Room catalog, so
  `savant_data` and `savant_dictionary` are unchanged. It is what lets SQL pool by position, and lets a
  stability study take its prior within position, the way the page does.
- **The function bundle** is **106.7 MB** of the 250 MB limit (DuckDB is 97.2 MB of it). No new function: the
  bench is inside `api/mcp.js` (still 12 of Hobby's 12).

### Security, test by test

Each item is refused twice: once by the checker in `api/_sql.js`, and once by the locked engine when the
statement is sent straight past the checker.

| attempt | result |
|---|---|
| Writes: `INSERT`, `CREATE`, `COPY`, `UPDATE`, `DELETE`, `DROP`, `CREATE MACRO`, temp tables | refused: only one `SELECT` serializes |
| `ATTACH`, `INSTALL`, `LOAD`, `SET`, `PRAGMA`, `RESET`, `CALL`, `DETACH`, `EXPORT`, `CHECKPOINT` | refused. The engine: "configuration has been locked", "loading external extensions is disabled", permission errors |
| Other URLs and paths: `read_parquet`, `read_csv`, `read_text` and `read_blob` on other sites and `/etc`, `FROM '<url>'`, `glob`, `parquet_metadata`, `query()`/`query_table()`, SQL in a string, traversal past the allowlist, the release's other files by URL | refused. The engine allows exactly the Data Room files: `enable_external_access=false` plus `allowed_paths`, exact URLs, so traversal fails too |
| `getenv` and every other way to see settings: `current_setting`, `duckdb_settings`, `duckdb_secrets`, `duckdb_extensions`, `which_secret`, `information_schema`, `version()` | refused. The engine has no `getenv` at all |
| Two statements | refused |
| A query built to exhaust memory | stopped with "needed more than this tool's 1GB of memory … narrow it". Nothing spills to `/tmp`, and the engine still answers the next query |
| A query built to run past the time limit | interrupted at the cap (22 s in production; 2.5 s in the test) with a way to narrow it |

### Limits

- **Rows:** 500 returned, with the full count.
- **Wall time:** 22 s (the function's limit is 30 s).
- **Memory:** 1 GB for DuckDB (the function has 2 GB), 4 threads.
- **Scan budget:** 25 MB of compressed columns per scan, estimated from `EXPLAIN` before anything is read.
  `SELECT *` over every season of NFL plays (39 MB), CFB plays (40), NFL player-games (28) or NBA shots (57)
  is refused with how to narrow it. A handful of columns league-wide is well inside it.

one-column scan of every season of NBA shots read 41 MB of the 57 MB table. The range reads work and skip
unread seasons entirely. At these file sizes they rarely skip unread columns.

## Refresh

`pipeline/dataroom/parquet_publish.sh <sport> [season]` runs after a sport's JSON is published:

- **Where it runs:** from `publish.sh`, which covers NBA, NFL, CFB and UFC, and from the college run's
  `publish()`.
- **What it does:** rewrites that season's Parquet for each of the sport's tables from the same JSON, checks
  it, and uploads only files whose bytes changed. The output is byte-deterministic: a second run uploads
  nothing.
- **On failure:** the same rule as the JSON. Every failure is a `::warning::` and the script exits 0. If any
  upload fails the manifest is put back, so it never claims rows the release does not have.
- **Tried once by hand on UFC 2026.**
- **Not yet exercised:** a cloud run, where it installs its own dependencies.

From a checkout with the store's credentials (`vercel env pull` writes them):

```

KV_REST_API_URL=… KV_REST_API_TOKEN=… node tools/keys/tier.mjs <co-founder's email> founder
```

- **Dry run:** `--dry-run` shows what would change.
- **Taking it away:** `none` removes the tier.
- **What it prints:** key ids only, never a key.
- **When it takes effect:** within ten minutes (the key cache).
- **If the co-founder has no key:** they get one free at wcehoops.com/#ai first, and the command says so if
  they don't.

## Judgment calls

1. **The founder listing folds `savant_data` and `savant_dictionary` into `savant_sql`.** It was the only
   way under 90,000 without touching public tools or dropping `savant_query`.
2. **All Parquet is on the release,** small tables included: one host, one allowlist, nothing in git.
3. **`nba.player_seasons`, an analysis-only table.** Stability parity needs the page's positions. With the
   league mean as the prior instead, only 5 of 14 stats came within 20%. With positions, all 14 do.
4. **Errors match statsmodels.**
   - OLS clustered: CR1, t on G−1.
   - OLS unclustered: classical.
   - Logit: z intervals, statsmodels' default, with the same CR1 factor.
5. **`compare`'s headline interval is the cluster bootstrap,** seeded so the same request gives the same
   answer, with the analytic CR1 test beside it. The bootstrap's resample count drops when clusters × groups
   is large, to a floor of 400. A study with no cluster column is refused past 200k rows (500k for trend).
6. **Scan budget of 25 MB of columns,** estimated from the plan. The brief's example (every NFL play, every
   column) is past it.
7. **The bench lives in `api/mcp.js` behind `GET ?bench=1`, preview deployments only.** Production still
   answers 405 to a GET. It runs a fixed list of queries; nothing a caller sends reaches the engine.
8. **Extensions:** httpfs is fetched from extensions.duckdb.org on a copy's first call (about 1 s of the cold
   start) rather than committed to git.
9. **The `cbb` 2018-19 minutes difference** is a page-side inconsistency, reported, not hidden or tuned
   away.
10. **The exam's analysis questions run against a founder-tier connector.** Locally that is an in-process
    founder server. The weekly live run skips them unless `WCE_EXAM_KEY` holds a founder key.

## Not built, or cut

- **No study type was cut.**
- **The weekly live exam can't ask the 20 analysis questions** without a founder key in the workflow's
  secrets.
- **Cold-start setup is 1 to 2 s** on top of the first query of a new copy. Bundling httpfs into the
  deployment would save about 1 s, at the cost of a build-time download.
